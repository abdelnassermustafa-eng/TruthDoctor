# TruthDoctor V3 — Architecture and Deployment Specification

## Product Model

TruthDoctor V3 is planned as one universal infrastructure
platform with two application editions:

- **Desktop:** Self-contained, installable on macOS,
  Windows and Linux.
- **Web:** Browser-accessible over HTTPS, using hosted
  backend services and appropriate multi-user security.

Both reuse shared business and provider functionality.
Neither edition depends on the other to operate.

## Desktop Installation Contents

The release package includes:

- Native TruthDoctor desktop application and Avalonia UI
- TruthDoctor-owned application and backend services
- Universal Provider Framework and capability registry
- Bundled default and selected optional provider packages
- Required .NET runtime components
- Configuration, diagnostics and local storage support
- OS-integrated secure credential handling
- Application version, upgrade and rollback metadata

No separate TruthApi process, .NET SDK or web server
shall be required for the standalone desktop edition.

## Provider Selection During Installation

Provide independent checkboxes and Select All behavior.

Users may select one, multiple or all available providers.

AWS is recommended initially, but may be deselected.

Potential providers include AWS, Azure, Google Cloud,
VMware vSphere, Kubernetes and supported network devices.

These are implementation targets, not claims that all
provider integrations are currently complete.

Install only release-approved packages that satisfy
signature, integrity, version and dependency checks.

Support subsequent installation, update and removal
without reinstalling the entire desktop application.

## First Launch and Provider Discovery

The user selects an installed provider, configures its
connection, completes authentication, and grants access.

TruthDoctor verifies credentials and permissions.

Authorized discovery may start automatically where the
user has enabled the relevant discovery policy.

Support multiple provider connections, individual discovery
and combined infrastructure discovery.

Discovery shall default to read-only access.
Infrastructure-changing operations require distinct
authorization and existing operation safeguards.

## Provider Lifecycle States

- Available
- Selected
- Installed
- Enabled
- Configured
- Authenticated
- Connected
- Discovering
- Ready
- Expired
- Failed
- Update available

Installation alone does not imply AWS authentication
or successful infrastructure discovery.

## Provider Package Security

Provider binaries must be verified, version-compatible
and acquired through a trusted distribution mechanism.

Unsigned or incompatible executable modules must be rejected.

Customer credentials must never ship inside installers.

Untrusted executable providers require an appropriately
isolated execution architecture before activation.

## Browser Edition

The browser edition uses centrally hosted services,
provider integrations and secure HTTPS transport.

It shall preserve desktop-independent shared contracts.

It requires identity, role-based or equivalent authorization,
auditing, secure sessions and tenant isolation when applicable.

Browser clients shall not receive privileged credentials
or install native executable provider packages.

## Development and Release Gates

- Independent AWS authentication and discovery
- No separately running TruthApi dependency
- Complete G3.21–G3.27 functional acceptance
- Full unit and integration regression
- Multi-provider selection and installation verification
- Secure credential and package validation
- Cross-platform clean-machine installation
- Upgrade, rollback and uninstall acceptance
- Explicit approval before customer deployment
